# Application catalog layouts and logos (Phase 4.3)

The 115-entry Phase 4.2 catalog, its package identifiers, profiles, selection rules, conflicts,
dependencies and installation engine are unchanged. Only the presentation changed.

## Four layouts

| Layout | Shows | Notes |
|---|---|---|
| Logos | logo tile + check mark | name in the tooltip (`title`) and as the checkbox's accessible name |
| Grid (default) | logo, name (wraps to two lines), check mark | tiles keep one width; full name in the tooltip |
| Compact | checkbox, small logo, name | dense, one line each |
| Detailed | checkbox, logo, name, reason ("Selected by …"), method, category, warnings, description; package metadata in Advanced view | the Phase 4.2 row |

* Every layout is a real `<input type="checkbox">` bound to the same selection (`setApp`), so
  switching layouts, searching, filtering, switching profiles, moving between wizard steps or
  modes never changes what is selected. Each item carries `data-app` and `data-state`.
* The selected state is a filled check mark plus a border, not colour alone. Manual follow-up,
  antivirus group and blocked apps carry small symbols; the reason, blocking conflict and manual
  note are also in the accessible description.
* Keyboard: Tab to a tile, Space toggles; focus is visible on the tile.
* The chosen layout is a per-browser preference (`wdb.catalogView`).
* Counters: in the catalog, selected (with "+n required" for dependencies), to install, manual
  follow-up, warnings or conflicts, unticked by you, profiles active.
* Reasons now read "Selected by Core Essentials" / "Selected by Network Engineer / Developer /
  Technician" (previously "Universal default" / "Default in …").

## Logo sources

Generated by `node scripts/build-app-icons.mjs` into `public/app-icons/` with provenance in
`src/data/apps/icons.json`. Nothing is hotlinked at run time; images load lazily from the site
itself, so the catalog works offline and checkboxes never wait for an image.

| Source | Apps | License / note |
|---|---|---|
| Simple Icons 16.33.0 (`simple-icons`, pinned devDependency) | 62 | CC0-1.0 icon data. The marks remain trademarks of their owners and are used only to identify the application. Each path is drawn on a rounded tile in the brand's own colour. `kind: publisher` marks the publisher's mark (e.g. Apple for Apple Devices, Dell for Dell Command \| Update). |
| Rufus repository (`pbatard/rufus@3e696ab`) | Rufus | GPL-3.0; Store tile PNG |
| Ventoy repository (`ventoy/Ventoy@582704c`) | Ventoy | GPL-3.0; 64 px PNG |
| SABnzbd repository (`sabnzbd/sabnzbd@9748bcf`) | SABnzbd | GPL-2.0-or-later; SVG |

65 of 115 apps have a logo. The other 50, including every Microsoft product (Microsoft asked Simple
Icons to remove its marks), most utilities and the runtimes, show an **initials tile** in the
category colour. No logo was drawn or invented. A logo whose file fails to load falls back to the
same tile.

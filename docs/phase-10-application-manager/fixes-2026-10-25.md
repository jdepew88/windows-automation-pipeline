# Application Manager 1.0.1: fixes from the first real-world test (2026-10-25)

The evidence came from the caches the agent left on the test computer
(`%LOCALAPPDATA%\WindowsDeploymentBuilder\AppManager`): `updates-cache.json` (96 updates) and
`inventory-cache.json` (167 WinGet packages, 594 Windows programs). They were only read; nothing was
installed, updated or removed.

## Bug 1: every available update shown under Source and refused

**Symptom.** The Updates page showed the newer versions under Source, and every package was marked
ineligible with "No newer version is listed". Examples: 7-Zip 25.01 → 26.05, VLC 3.0.21 → 3.0.24,
Chrome 155 → 156, Wireshark 4.4.3 → 4.6.9. In the cache, all 96 items had `available: ""` and the
new version in `source`.

**Root cause.**
- The agent checks for updates with `winget upgrade --source winget`. When a command names a
  source, WinGet leaves the Source column out of its table: `Name Id Version Available`.
- `ConvertFrom-WamTable` assigned columns by how many there were: 4 columns meant
  `Name Id Version Source`. So the Available values became Source, Available was empty, and the
  eligibility check refused every row.
- The simulated WinGet in the tests always printed a Source column, so the suite never saw the real
  layout.

**Fix.** In `AppManager.ps1`, `Read-WamTable` identifies columns by their titles (WinGet's `Name`,
`Id`, `Version`, `Available`, `Source`, `Match`), never by count. In another display language the
first three columns are Name, Id and Version. A later column is Source only if every value in it
is a source name (`winget`, `msstore`); otherwise it is Available.
- **Cells:** columns are cut by console cells, as WinGet aligns them (East Asian wide characters
  take two cells).
- **Rows:** a row must have a space before every column it reaches. Summary and note lines end a
  table.
- **Values:** shortened values ending in "…" are marked, and identifiers are kept exactly.
- **Inconsistent rows** (a source name read as a version, a version read as a source, no version)
  are reported. When any are found, the check gets the status `parseError`, nothing from it is
  eligible, and the raw output is saved to `logs\last-update-check-<source>.txt`.

Eligibility (`Get-WamEligibility`) now requires all of the following:
- the row was read cleanly;
- the identifier is exact (not shortened) and a WinGet or Store identifier;
- WinGet's installed-package list (`winget export`) contains it;
- the installed version is known (not `Unknown` and not `< …`);
- the available version is newer;
- the package is not in WinGet's explicit-upgrade table, not explicit in the catalog, and not
  WinGet's own App Installer (updating it would end the running WinGet).

The page checks again (`updateIssue` and `bulkEligible` in `src/engine/manager/index.ts`, with
version comparison mirrored by `compareVersions`). It refuses a row whose values cannot be right,
whatever the agent says: such rows show **Could not read**, and **Update all eligible** takes a
package only when both agree.

Caches written by the first parser are ignored (they carry no `parser: 2`). Until the next scan or
check, the page shows "not scanned" or "not checked", never the misread values.

**Result on the real data.** Rebuilt in WinGet's layout from the 96 cached rows (locally, not
committed), all 96 rows parse with no problems; 93 are eligible. The three exclusions are correct:
- App Installer (WinGet's own package);
- Ubisoft Connect (installed version `< 174.2.0.13389`);
- Discord (WinGet's explicit-upgrade table).

## Bug 2: installed programs appear, then disappear

**Symptom.** The Installed tab showed about 592 more programs, then removed the list almost at once.

**Root causes.**
1. Those programs were in a `<details>` element. The page re-renders on every background poll
   (every 1–4 s) and patches the DOM to match a freshly built tree. That tree had no `open`
   attribute, so the patch removed the one the browser set when the list was expanded: the list
   collapsed on the next poll.
2. Only the first 500 were drawn (`programs.slice(0, 500)`).
3. Every poll replaced the state, and responses were applied in arrival order. A slow, older
   response could overwrite a newer one: for example a poll started before a scan finished,
   arriving after the refresh that followed the scan.
4. The Windows programs were never reconciled with the WinGet packages. Programs WinGet manages
   appeared again as "other programs", and nothing told the three kinds apart.

**Fix.**
- `installedView` (`src/engine/manager/index.ts`) lists every program once, in one of three groups:
  - **In the catalog:** matched by WinGet identifier, or uncertain by Apps & Features name.
  - **Other WinGet packages:** exact identifiers from `winget export`.
  - **Other programs:** Windows uninstall records, and MSIX packages WinGet does not match to a
    source. These have no identifier and no removal checkbox; the page says they need their own
    installer or Settings > Apps.
- A Windows program is the WinGet package that `winget list` (now part of the read-only inventory)
  shows under the program's name; shortened names match by prefix. Duplicate uninstall records
  (same name and version) are shown once. If `winget list` cannot be read, nothing is dropped and
  the page says the programs could not be linked.
- **Rendering.** No `<details>`. Every row is drawn. The group (All, In the catalog, Other WinGet
  packages, Other programs, each with its count) and the search live in page state, so a refresh
  keeps them.
- **Stale responses.** State requests are numbered; a response is applied only if no later
  request's response was applied before it. An unchanged state is not redrawn. One failed poll keeps
  the last state on screen, and only three in a row mean the agent stopped.
- **Atomic inventory.** The agent builds a new inventory in two steps (export, then list) and
  publishes it only when both are done. Meanwhile the page keeps showing the previous list with
  "Scanning again… this list stays until the new scan is complete" (`scanning` and `checking` in
  the agent state).

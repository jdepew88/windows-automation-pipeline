# Application catalog (Phase 4.2)

The catalog is data, not code: `src/data/apps/catalog.json`, generated by
`scripts/catalog-source.mjs` from the hand-written entry list in that script plus the recorded
verification (`verification-2026-10-21.json` in this folder). It is validated when the app loads
(`src/engine/applications/catalog.ts`), so a broken entry fails loudly. Being listed installs
nothing: an app is installed only when it is selected.

## Entry schema (catalog version 2)

Version 1 fields are unchanged; version 2 adds optional fields, so an entry written for version 1
still validates (without `method` it installs from its `source`).

| Field | Meaning |
|---|---|
| `id` | Stable internal id (`chrome`, `claude-code`). Profiles refer to apps by this id, never by name. |
| `displayName`, `description`, `category`, `website` | For people. `website` must be `https://`. |
| `packageIdentifier`, `source` | The exact WinGet or Store id and its source; `null` / `"none"` for manual entries. Identity in a selection is always *source + identifier*. |
| `method` | `winget`, `msstore`, `portable`, `vendor` or `manual`. |
| `architectures` | Architectures with a native installer, from `winget show --architecture`. x64 apps also run on Arm64 under emulation. |
| `scope`, `installerType`, `license` | From the verification output where WinGet reports them. |
| `requires` | Package keys this app needs; they are added to the plan automatically and installed first (Docker Desktop → WSL, HandBrake → .NET Desktop Runtime 8). |
| `interaction` | `silent`, `mayPrompt`, `required` (never attempted unattended), `unknown` (not reviewed). |
| `accountSignIn` | Useful only after the customer signs in. The installation is still unattended; no account is ever configured. |
| `reboot` | `none`, `mayRequire`, `unknown`. |
| `selectionWarning` | Shown whenever the app is selected (iCloud data volume, Malwarebytes real-time protection, antivirus). |
| `conflictGroup` | `realtime-antivirus`: at most one of Avast, AVG, Avira. |
| `portable` | `{ executable, shortcut }` for portable entries (see below). |
| `manual` | `{ reason, instructions, url }` for manual entries. |
| `validation` | `{ status, checkedAt, method }`: `verified` (found by `winget show`, with name, version and publisher recorded), `manual`, `unverified` or `unresolved`. |

The file also lists `excluded` apps (owner decisions): Brave, Opera, Vivaldi, Pidgin, Dropbox,
SugarSync, LibreOffice, Foxit Reader, PDF24 Creator, CutePDF, Ghostscript, SumatraPDF, Paint.NET,
Krita, IrfanView, Greenshot, ShareX, WinDirStat (WizTree is preferred) and Apple TV. They are shown
under "Not offered". Someone who really needs one can still add it by its exact WinGet ID; it is
then installed like any other package and the plan notes that it is not in the curated catalog.

## How identifiers were verified

Only read-only commands were used on the development computer; nothing was installed or removed.

1. `winget search <name>` in both sources for every requested app, to find candidate ids.
2. `winget show --id <id> --exact --source <source>` for every candidate, recording name, version,
   publisher, homepage, licence, installer type and URL (and pricing for Store apps).
3. `winget show … --architecture x64|arm64|x86`: an architecture counts only when WinGet prints an
   installer for it ("No applicable installer found" otherwise).
4. For ids that `winget show` did not find, the winget-pkgs repository on GitHub was checked as
   well (manifest folders), so "not found" is not a search glitch.
5. For portable packages, the installer manifests were read to get the real file names.

`scripts/catalog-source.mjs` refuses to generate an entry whose identifier is not in the
verification output, and `tests/unit/app-profiles.test.ts` checks every catalog identifier against
it again. Identifiers are never guessed.

## Portable applications

Portable tools are installed through WinGet, not by a downloader of our own:

* WinGet downloads the file from the publisher URL in the community manifest and **checks its
  SHA-256** before using it; a mismatch fails the installation (`INSTALLER_HASH_MISMATCH`).
* The engine always installs portable packages with `--scope machine`, so WinGet puts them under
  `%ProgramFiles%\WinGet\Packages\<id>_<source>` (administrator-only), links them on PATH, and keeps
  version tracking (`winget list`, `winget upgrade`). That is Windows' own convention for machine-wide
  portable apps; no new folder under Program Files is invented.
* After a successful (or already present) installation the engine creates
  `Start Menu\Programs\Windows Deployment Tools\<shortcut>.lnk`. The target is found by a file-name
  pattern (`rufus*.exe`, because the file name carries the version) inside the package folder only:
  depth at most 4, links and junctions are skipped, every match must resolve inside the folder, and
  the shortest path wins. Re-running replaces the same shortcut, so there are never duplicates.
* Patterns and shortcut names are plain names (`PORTABLE_EXE`, `SHORTCUT_NAME`); anything with a path,
  quote or separator is refused before WinGet is called.
* Nothing is extracted by our code, no post-extraction script runs, and the tools are never started.
  Rufus and Ventoy are only installed; formatting a drive is always a manual action by a person.
* If the shortcut cannot be created, the package stays installed and the shortcut is listed for
  follow-up.

## Security software

* Avast, AVG and Avira are real-time antivirus products in one conflict group. The UI disables the
  others once one is ticked, and a combination that arrives through an import blocks generation
  with a message.
* Selecting any of them shows that Microsoft Defender Antivirus switches itself to passive mode when
  a third-party real-time antivirus registers. The deployment never changes Defender, Windows
  Firewall or UAC settings.
* Malwarebytes can be combined with an antivirus as an on-demand scanner, but the installer cannot
  guarantee on-demand-only behaviour (a Premium trial or licence enables real-time protection), so it
  always carries a warning, and a second warning appears when it is combined with an antivirus.
* SUPERAntiSpyware (free edition) is on-demand only; Spybot S&D is a manual follow-up.

## Runtimes

Core Essentials includes the Visual C++ 2015-2026 redistributables (x64 and x86). Like every
package, they are checked with `winget list` first and skipped when a compatible version is already
installed (`AlreadyInstalled`). Other runtimes are optional: .NET Desktop Runtime 8 and 10, ASP.NET
Core 8 and 10, Eclipse Temurin 25/21 JRE and 25 JDK, VSTO runtime, legacy Visual C++ 2010/2012/2013,
and .NET Framework 3.5 (a Windows feature, so a manual follow-up). Runtimes are added automatically
only when a selected app declares them in `requires`. No browser plug-ins (Flash, Silverlight) are
offered: streaming sites depend on the browser's own DRM support.
